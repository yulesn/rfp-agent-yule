# 의존성 설치가 매우 오래 걸리고 .venv 가 6GB
- 날짜: 2026-11-11 / Phase 1 / 관련 파일: `pyproject.toml`, `uv.lock`

## 증상
`uv add langchain ... sentence-transformers ...` 를 한 번에 실행했더니 10분 제한을 넘겨 백그라운드로 전환되었고, 완료까지 약 20분이 걸렸다. 끝난 뒤 `.venv` 가 약 6GB 였다.

## 시도한 것
- 실패한 설치는 없었음(에러 없이 완료). 대기만 했다.
- 중간에 `uv.lock` 은 먼저 생성되고 실제 설치(다운로드)가 뒤에서 오래 진행되었다.

## 원인
`sentence-transformers` 가 `torch` 를 끌고 오고, Linux 기본 torch 휠은 CUDA 라이브러리(nvidia-*)를 함께 받는다. 로컬 임베딩(BGE-M3, ADR/플랜 3절 6번)을 CPU 로 쓸 예정이라도 기본 설치는 GPU 용 패키지까지 포함한다.

## 해결
- `pyproject.toml` 에 `torch` 를 명시 의존성으로 추가하고, macOS 외 플랫폼은 CPU 전용 휠 인덱스(`pytorch-cpu`, `explicit = true`)를 쓰도록 `[tool.uv.sources]` 를 설정했다. 리뷰에서 노트북/CI 에 6GB CUDA torch 는 부적절하다는 지적을 받고 반영.
- 이 작업 컨테이너는 `download.pytorch.org` 가 외부 접속 허용 목록에 없어(프록시 403) `uv lock` 을 다시 돌리지 못했다. 그래서 `uv.lock` 은 아직 CUDA 버전 그대로이고 `.venv` 도 6.1GB 다.
- 할 일: 해당 호스트에 접근 가능한 환경(Yule 노트북)에서 `uv lock && uv sync` 후 `uv.lock` 을 커밋한다. 그 전까지 CI 의 `uv sync --locked` 는 lock 불일치로 실패한다.
- 테스트는 무거운 라이브러리를 lazy import 하므로 `uv run pytest` 는 2초 안에 끝난다.

## 배운 점
로컬 임베딩을 쓰면 의존성 용량과 설치 시간이 CI/배포 비용이 된다. CPU 전용 휠 설정은 처음부터 해 두자.
