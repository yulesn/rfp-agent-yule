# 파일명 NFD 문제와 HWP 파서 무한 루프

- 날짜: 2026-11-11 / Phase 1 / 관련 파일: `scripts/inspect_data.py`

## 증상
- 탐색 스크립트가 10분 넘게 끝나지 않음 (원본 100개여야 하는데 `[n/200]` 로 200개 처리 중).
- 수정 후에도 65번째 파일(케빈랩 HWP)에서 CPU 100% 로 멈춤.

## 시도한 것
1. 처음엔 PDF `find_tables` 가 느린 줄 알고 PDF를 단독 측정 → 4건 모두 수 초라 아님.
2. HWP 6건 단독 측정 → 파일당 0.1~0.2초라 평균적으로 아님. 진행 로그를 넣어 보니 사본까지 200개를 처리하고 있었음.
3. 원인 1: `"의 사본" in p.name` 비교 실패. macOS 는 파일명을 NFD(자모 분리)로 돌려줘 NFC 리터럴과 불일치 → NFC 정규화 후 비교하도록 수정.
4. 원인 2: 케빈랩 파일 하나만 `faulthandler.dump_traceback_later` 로 덤프 → `hwp_hwpx_parser/hwp5.py::_extract_hyperlink_texts_from_para` 에서 안 끝남. `ExtractOptions` 에는 하이퍼링크 추출을 끄는 옵션이 없어 우회 불가.

## 원인
- NFD/NFC 불일치, 그리고 파서 라이브러리의 특정 파일 대상 무한 루프.

## 해결
- 모든 파일명 비교 전에 `unicodedata.normalize("NFC", …)`.
- HWP 는 파일마다 별도 프로세스(spawn)에서 실행하고 60초 타임아웃, 초과 시 kill 후 `timeout` 으로 기록.

## 배운 점
- 한글 파일명은 항상 NFC 로 정규화해서 비교하고, 외부 파서는 파일 단위 격리·타임아웃 없이 배치로 돌리지 않는다.
