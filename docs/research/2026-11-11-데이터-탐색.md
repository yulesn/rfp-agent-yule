# 데이터 탐색 결과 (Phase 1-1)

- 날짜: 2026-11-11 / Phase 1 / 스크립트: `scripts/inspect_data.py` / 원자료: `data/processed/inspect_report.json` (커밋 안 함)
- 문서 본문은 싣지 않고 숫자와 관찰만 정리했다.
- 참고: 처음 받은 `data/raw/` 에는 "…의 사본" 복사본 100개(원본과 바이트 동일)가 섞여 있었으나, 파일 관리 중 생긴 실수로 확인되어 삭제했다. 아래 수치는 삭제 후 원본 100건 기준.

## 1. 요약

| 항목 | 값 |

| 용량 | 합계 170.8MB, 중앙값 0.97MB, 최대 24.1MB |

| 컬럼 | dtype | 결측 | 의미 추정 / 비고 |
| --- | --- | --- | --- |
| 공고 번호 | str | 18% | 나라장터식 공고 ID(예: 20241001798). 결측 18건은 HWP 16 + PDF 2. 값이 있는 것은 중복 없음 (고유 82) |
| 공고 차수 | float | 18% | 재공고 차수 (0.0이 76, 1.0이 4, 2.0이 2). 공고 번호와 같은 행이 결측 |

| 사업 금액 | float | 1% | 원 단위. 중앙값 1.7억, 최대 141억, **0원 6건 + 결측 1건**(미공개/미정 추정) |
| 발주 기관 | str | 0% | 고유 87개 기관 |

| 파일명 | str | 0% | `{발주기관}_{사업명 앞부분}.{ext}` 형태(사업명은 잘려 있음). 조인 키 |

- **조인 키**: 별도의 doc id가 없다. `공고 번호`는 18% 결측이라 못 쓰고, **`파일명`이 유일하게 완전한 키**다. doc_id 는 파일명(NFC 정규화)에서 만들어야 한다.

## 3. 놀라운 점

1. **CSV `텍스트` 컬럼은 본문 전체가 아니다.** 중앙값 2.8천자(89~1.8만자)인데 파서가 뽑은 본문은 중앙값 7.5만자로 평균 수십 배 차이. 파서 결과가 CSV 텍스트를 포함하지도 않는다(앞부분 일치 확인 시 불일치). 즉 CSV 텍스트는 다른 추출기로 만든 발췌본이며, **색인용 본문 소스로는 부적합**하다. 직접 파싱이 필요하다.
2. HWP 파서가 **특정 파일 1건에서 영원히 끝나지 않는다** (`hwp5.py` 하이퍼링크 추출 루프). 파일 단위 타임아웃이 없으면 배치가 멈춘다.
3. macOS 파일명은 NFD 라서 코드의 한글 리터럴(NFC)과 비교가 안 맞았다 → 모든 파일명 비교 전에 NFC 정규화 필요.
4. 표가 압도적으로 많다(HWP 파일당 중앙값 121개). 예산·일정·평가기준이 표 안에 있을 가능성이 높다.
5. PDF 가 4건뿐이고 스캔본이 없어 OCR 은 당장 필요 없다. 반대로 HWP 가 96%라 **HWP 파싱 품질이 곧 전체 품질**이다.
6. PyMuPDF 가 PDF 1건에서 `MuPDF error: syntax error: invalid key in dict` 경고를 낸다(서울특별시_지도정보 PDF). 텍스트는 정상 추출됨.

## 4. 파싱에서 본 문제

- HWP: 1건 타임아웃(케빈랩 주식회사_영상감시 시스템 건, 약 1.1MB). 파서 버전 의존 버그라 우회(프로세스 격리+타임아웃) 필요. 이 1건의 대체 수단(예: CSV `텍스트` 발췌 사용, 다른 파서 시도)은 Phase 5에서 결정.
- HWP 파일당 처리 시간은 0.1~0.5초로 빨라서 100건 전체 파싱 비용은 문제 없음.
- 본문 대비 표 비중이 커서, 표를 평문으로 풀면 문맥이 깨질 수 있음(실제 품질은 미확인, Phase 1-2 샘플 점검 필요).

## 5. 설계 시사점

| 영역 | 시사점 |
| --- | --- |
| 파서 | 최소 파서는 HWP=`hwp-hwpx-parser`, PDF=PyMuPDF로 충분히 시작 가능. 파일 단위 프로세스 격리+타임아웃, 실패 문서는 목록으로 남기고 건너뜀. |
| 청킹 | HWP 는 쪽 정보가 없어(페이지 번호 불가) 인용은 `문서명 + 섹션/청크 번호`가 현실적. PDF 만 쪽 번호 가능. 문서가 길고(7.5만자 ≈ 1000자 청크 80개) 표가 많아 고정 길이 시작 → Phase 5에서 표 단위 보존 실험 |
| 메타데이터/`filter_rfps` | 조인 키는 파일명. 사업 금액 0원·결측, 마감일 8% 결측, 시작일 26% 결측을 "정보 없음"으로 처리하고 필터 결과에 명시해야 함. 날짜는 문자열이라 datetime 변환 필요. 기관명은 표기가 다양(87종)해 부분 일치 필터 권장 |
| 평가셋 | 메타 질문(예산/마감)은 CSV 가 정답 근거이므로 exact match 가능하나, CSV 결측 항목은 "답 없음" 문항 후보 |
