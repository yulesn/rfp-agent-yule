# 0005. HWP 파서는 hwp-hwpx-parser 1.0.0 + 경계 검사 패치를 유지한다
- 상태: 확정됨 (2026-11-11)
- 날짜: 2026-11-11
- 결정자: Yule (+ Claude 제안)

## 맥락
Phase 1 최소 파서로 `hwp-hwpx-parser` 를 쓰기로 했는데, 두 가지 문제를 확인했다.
- 케빈랩 HWP 1건에서 파서가 무한 루프에 빠진다 (원인: `docs/trials/2026-11-11-hwp-파서-무한루프-원인.md`).
- 확인일(2026-11-11) 기준 GitHub 저장소(`KimDaehyeon6873/hwp-hwpx-parser`)가 404 이고, PyPI 마지막 릴리스는 2026-01-29(1.0.0)다. 사실상 유지보수가 끊겼다.

## 결정
- 지금은 `hwp-hwpx-parser` 1.0.0 을 그대로 쓰고, 알려진 무한 루프는 **경계 검사 패치**(`_extract_hyperlink_texts_from_para` 를 임포트 시 한 번 감싸는 작은 몽키패치)로 막는다. `.venv` 의 라이브러리 파일은 수정하지 않는다.
- 파일 단위 프로세스 격리 + 타임아웃(`ingest.timeout_sec`)을 유지해 미지의 입력에도 배치가 멈추지 않게 한다.
- 교체 후보(dochan, unhwp, syhwp, rhwp-python)와의 비교는 **Phase 5** 에서 표 품질 중심으로 한다.

## 근거
- 측정(2026-11-11, 96개 HWP): 패치 없이 95/96 성공(케빈랩 타임아웃), 패치 후 96/96 성공. 케빈랩은 0.22초, 56,932자, 표 137개. 기준선 전체는 파일당 중앙값 약 0.3초, 마크다운 표 중앙값 약 112개/파일.
- 후보 비교는 시간이 들고 Phase 1 의 목적("끝까지 한 번 돌리기")과 맞지 않는다. 품질 개선 단계(Phase 5)에서 평가셋으로 비교하는 편이 근거가 단단하다.

## 영향 / 위험 / 되돌리는 방법
- 위험: 업스트림 수정이 없어 새 입력에서 다른 버그가 나올 수 있다 → 타임아웃/격리와 실패 목록 로깅으로 완화.
- 의존성은 `==1.0.0` 수준으로 고정해 패치 대상 코드가 바뀌지 않게 한다 (패치 함수는 원본을 감싸므로 업스트림이 고쳐져도 안전).
- 파서 교체 시 `ingest/hwp.py` 한 곳만 바꾸면 된다 (`parse_hwp(path) -> RfpDocument` 계약 유지).
