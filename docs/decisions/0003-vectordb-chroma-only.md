# 0003. 벡터DB는 Chroma만 사용 (SQL 서버 없음)
- 상태: 제안됨 (Yule 제안, 플랜 컨펌 시 확정)
- 날짜: 2026-11-11
- 결정자: Yule

## 맥락
v0.1 플랜은 메타데이터 SQL 필터와 배포 통합을 이유로 PostgreSQL + pgvector를 추천했다.
Yule이 100건 규모에 SQL 서버까지 둘 필요가 있는지 의문을 제기하고 Chroma만 쓰자고 제안했다.

## 후보 비교
| 후보 | 장점 | 단점 |
| --- | --- | --- |
| Chroma (로컬 파일) | 서버 불필요, 설정 0, 파일 하나로 배포, 팀 레포와 동일 | 대규모·동시 쓰기에 약함, 범위 필터는 숫자형만 |
| PostgreSQL + pgvector | SQL 조건 검색, 앱 DB와 통합 | DB 서버 운영·호스팅 비용, 100건엔 과함 |

## 결정
Chroma만 사용한다.
- 청크 검색: Chroma (메타데이터 `where` 필터: doc_id, 기관, 분야 등)
- 문서 단위 조건 검색(`filter_rfps`: 예산 범위, 마감일, 기관): 메타데이터 CSV를 pandas DataFrame으로 로드해 처리 (100행이라 메모리로 충분). 날짜·금액은 숫자형으로 정규화
- 고객사 프로필·대화 기록은 처음엔 JSON 파일/메모리 checkpointer, 필요해지면 SQLite

## 근거
문서 100건 규모, 비용 최소 원칙, 무료 호스팅 배포 용이성. 검색 계층을 `retriever` 모듈 뒤에 두어 나중에 교체 가능.

## 영향 / 되돌리는 방법
분산 처리(Phase 8)에서 여러 API 인스턴스가 같은 인덱스를 읽을 때는 읽기 전용 파일 복제로 충분. 쓰기 동시성이 필요해지면 Chroma 서버 모드나 pgvector로 이전 검토.
